# Case: overall score looks passable but the single most load-bearing fact is missing

**Reviewer:** `acceler-post-sales:discovery-fit-reviewer` / `discovery-fit-review/SKILL.md` §1.2
**Source:** the skill's own explicit flag — "a brief that scored ≥80% overall but has no real answer to that one MUST item still produces an incomplete Facts Sheet."

## Input

A discovery brief that answers most of the 33-question checklist reasonably (audience, tools, timeline, budget all covered) but never gets a real answer to "what does success look like 3 months out" — the closest thing on record is a vague "we want people to feel more confident with AI."

## Expected

- Verdict: the discovery-checklist score itself may land ≥80%, but the reviewer must flag the Facts Sheet as incomplete specifically because of this one fact, regardless of the aggregate score.
- This should read as its own distinct finding, not get averaged away by an otherwise-strong score.
- Escalation: per §3, this is a human action item ("go back and ask the client"), not something routed through the fix loop.

## Why this case exists

This is the exact scenario the skill was written to catch — a strong-looking aggregate score hiding the one gap every downstream reviewer depends on most. If the reviewer only reports the aggregate %, this failure mode goes undetected.
