# Changelog

This repo hosts two plugins in one marketplace: `acceler-presales` (root) and `acceler-post-sales` (`post-sales/`). Each versions independently in its own `.claude-plugin/plugin.json`; entries below are labeled by plugin. Bump the relevant plugin's `version` on every release so teammates' `/plugin marketplace update` picks up the change.

## acceler-post-sales [0.3.0] — 2026-09-10

### Content review (NEW) — per-type quality gates + session-level coherence check, before content ships
- **4 new single-artifact skills**, each independently reviewable right after that artifact is generated: `post-sales/skills/deck-review/`, `code-demo-review/` (notebooks + standalone code share one skill, checks overlap almost entirely), `mcq-review/` (kept separate from assignments — item-writing defects are a different failure mode from rubric defects), `assignment-review/`. Each SKILL.md splits into a tunable plain-English **Rules** section and a separate **Memories** log of human-dismissed findings (Kodus Kody Rules / Learnings pattern) so the rubric stays editable without touching orchestration logic, and repeat human dismissals stop being re-flagged.
- **`post-sales/skills/content-review/SKILL.md`** (rebuilt as orchestrator, v2) — runs the four per-type skills first, then adds the one check none of them can do alone: cross-artifact coherence (does the MCQ test what the deck taught, does the assignment reinforce the notebook, does difficulty escalate day-over-day). Includes risk tiering (high-stakes vs standard — borrowed from "tier by risk, not artifact type" production review practice) that scales *human attention depth*, never which hats run.
- **Human-gated fix loop, not autonomous auto-fix**: every FAIL is proposed with a suggested fix and requires explicit human approval before a fresh fixer agent applies it; the same original hat re-verifies fresh (never self-graded); max 2 rounds before escalating. Hard guardrail in every skill: the fixer may only edit the artifact, never the stated objectives or the rubric itself — the content equivalent of an agent "fixing" a failing test by rewriting the assertion (flagged in Addy Osmani's agentic-review writeup).
- **PR-vocabulary tier** (✅ Approve / 💬 Comment / 🔴 Request Changes) presented explicitly as a recommendation for the human checklist, never an auto-ship decision ("AI review is a sensor, not a verdict"). The 5-item human sign-off checklist reuses the honest GAP/THIN/partial-style flagging convention from `requirement-mapping`, preceded by a short plain-language walkthrough; a lightweight human command vocabulary (`explain` / `resolve` / `re-review`, borrowed from CodeRabbit) supplements plain approve/reject on each finding.
- **6 new commands**: `/acceler-post-sales:deck-review`, `:code-demo-review`, `:mcq-review`, `:assignment-review`, `:hands-on-guide-review`, `:project-review` for fast single-artifact feedback, plus `:content-review` for the full session-bundle pass.
- **Grounded against a 5-thread survey of ~15 real Acceler program folders** (Bosch, Nucleus, Cornerstone, Deloitte, ETS, 6 e& AI Builder variants, Lowe's, LVT, Yettel, PPF Hungary), not assumptions. Real findings folded into the rubrics: `hands-on-guide-review` (5th artifact type — standalone tool-access/setup docs, e.g. VM & AI Tools SetUp) and `project-review` (6th artifact type — capstone/multi-milestone projects with planted-bug grading and a verified reference-solution answer key; its central rule, quoting the source material directly, is that a rubric must distinguish "the agent complied" from "I saw the guardrail actually block it"); `code-demo-review` broadened to cover no-code/low-code build guides (Copilot Studio, Figma Make — confirmed across 3 independent program folders, not code-only); `mcq-review` gained multi-select-format detection (fixes a false-positive risk in the ambiguous-answer rule), explanation-completeness (a confirmed widespread gap — 3 of 4 sampled legacy sets had zero solution explanations), and topic-tag/difficulty-label/reuse-still-gets-checked rules; `assignment-review` gained the "starter kit gives you ~40%, state the split" rule and a weighted-rubric-table target shape; `deck-review` gained an explicit carve-out for Orientation/Closing Ceremony decks (logistics content, not Bloom's-taxonomy teaching content) and session-scoped alignment for single 60-90min masterclasses; the bundle orchestrator now excludes fixture/input data and post-delivery records (gradesheets, learner responses) from review scope. One open item, deliberately unresolved: a hybrid lesson/demo/assignment doc found in Cornerstone's content doesn't fit any of the 6 skills — flagged for more evidence before deciding if it's a genuine 7th type.
- **`post-sales/skills/agent-loops/SKILL.md`** (NEW) — the fix-loop mechanics (round bound, progress/spin-detection, maker/checker separation, the human-approval gate, the fixer guardrail) were duplicated near-identically across all 5 review skills; factored into one shared reference grounded in Addy Osmani's practical loop-engineering framework, so a mechanics change is one edit instead of five. Also documents the terminology distinction that matters here: every fix loop in this plugin is a bounded *goal* (runs until a condition is met), not a cadence *loop* — meant to be the shared pattern generation agents (Lesson Plan, Slide) reference too, not just review.
- Design grounded in real instructional-design frameworks (backward design/UbD, Bloom's Revised Taxonomy, worked-example/scaffolding-fade research, NBME item-writing guide) and checked against production multi-agent review practice (Qodo/CodeRabbit/Kodus architecture, Conventional Comments severity tiers, Quality Matters' 3-reviewer precedent, production code-review risk-tiering/human-in-the-loop lessons, and Osmani's loop-engineering framework) before locking — not guessed.
- **7 more pipeline-stage reviewers added**, each with its own skill/agent/command, grounded in either an existing in-repo spec or real local samples (Learner Onboarding Form response headers, Lesson Plan xlsx, Orientation/Closing Ceremony decks across 5 programs): `discovery-fit-review` (wires the existing `acceler-presales:discovery-checklist` into post-sales as a pipeline gate, extracts a Discovery Facts Sheet downstream reviewers check against), `onboarding-form-review` (checks the Learner Onboarding Form is actually tied to the stated program outcome, not generic intake), `lesson-plan-review` (the internal minute-level facilitator table — genuinely distinct from a Day-by-Day proposal or a deck; catches a real unchecked gap: row-duration sums never verified against stated session length), `orientation-review` and `closing-ceremony-review` (split into two skills, not one — Closing must hand off embedded assessment slides to `mcq-review` rather than duplicating that check; also resolved: a "Dry Run" deck is the same Closing deck rehearsed internally, not separate reviewable content — Live Tracker/Dry-Run ops tracking stays Control Panel territory as already agreed), `session-recap-review` and `impact-report-review` (post-delivery review of the two `session-recap` artifacts — the impact-report reviewer treats a fabricated quote attributed to a real, named learner as a high-severity factual-accuracy defect, escalated to a human immediately rather than run through the normal 2-round fix loop).
- **Folded in Acceler's own real module-creation checklist and historical review feedback** (Primary Research → Curriculum Design → Timeline Planning → SME Mapping → Module Creation → Module Review → Module Upload → Before/During/After the Class, plus real slide/notebook/MCQ/assignment feedback logs) as concrete rubric rules, not just the checklist headings: a new shared **Baseline Quality Bar** in `agent-loops/SKILL.md` (§2a) that every reviewer applies — zero spelling/grammar errors, formatting/notation consistency, no undefined acronyms, no duplicate slides, image citations — all grounded in real, repeated findings from actual review logs, not hypothetical nitpicks. `deck-review` gained a critical rule (no links to instructor-only solutions/notebooks accessible from student-facing slides, treated at security-finding severity), boilerplate/placeholder-demo-slide checks, and a slide-count-vs-duration sanity check (150+ slides for a 4-hour class was a real flagged pattern). `code-demo-review` gained explicit environment-setup and large-code-block-commenting checks. `assignment-review` gained a Setup & Resourcing Clarity rule (data-file docs, hardware spec, reference links). `project-review` now recognizes two legitimate house shapes, not one — the milestone/trap pattern (LVT) and a documentation-brief pattern (confirmed real: Motivation/Objectives/**role-relevance mapping**/Dataset/Prerequisites/Setup/Milestones/FAQs). `agent-loops` also now documents a dual human gate (internal review, then separately SME review — both real, distinct checkpoints per the house checklist, not one generic "human approves").
- **`audience-fit-review` (NEW, 8th artifact-adjacent reviewer)** — runs inside `content-review` alongside `coherence-reviewer`, but checks a genuinely different question: not "do the artifacts agree with each other" but "is this calibrated to the actual cohort and what the program promised them." Grounded in real threaded review comments on an actual e& Lesson Plan ("Cut the basic fundamentals... focus on practical," "Add more examples relevant to engineers") — direct evidence this class of defect is real, not hypothetical. Checks depth calibration against aggregated onboarding-form proficiency data, example/context relevance to the cohort's actual role, program-expectations fidelity against the Discovery Facts Sheet, and concern-responsiveness (does the content address what learners said they were worried about).
- **`onboarding-form-review` upgraded from reconstructed headers to a real pristine reference** (LVT's "Engineer Onboarding Form") — added Stack & Environment coverage for technical cohorts, a per-tool familiarity ratings matrix, and resolved an earlier open question: the "Discovery Form / Questions From Team Leads" the team asked about isn't a missing standalone artifact, it's a real, confirmed pattern — a conditional "FOR TECH LEADS · optional" section embedded inside the same onboarding form, not a separate document. No new skill needed for it; folded into `onboarding-form-review` §1.4.
- **Discovery Fidelity made a universal baseline check (`agent-loops` §2b), not just one reviewer's job** — direct response to the explicit ask: "matching the details we have from the discovery checklist... are we making sure that it is filled? That should be a proper pipeline." Every reviewer in the family now checks its artifact against the Discovery Facts Sheet where one exists, distinct from (and in addition to) each skill's own curriculum-alignment rule.
- **`lesson-plan-review` gained a cross-day demo-load-balancing rule**, grounded in a real threaded comment thread on an actual e& Lesson Plan xlsx ("Demos have to be lightweight as there are dedicated sections for demos in day 3") — a pacing defect only visible across the whole plan, not row-by-row.
- **`post-sales/evals/` (NEW) — golden test cases for the reviewer family**, grounded in real defects surfaced during this build (the MCQ Q11 near-duplicate distractors, the zero-explanation MCQ pattern confirmed in 3 legacy sets, a legitimate-multi-select negative case, the leaked-solution-link deck pattern, the undisclosed starter-kit split, LVT's compliance-vs-verified-enforcement rule, the missing-outcome-tie onboarding form, and the lesson-plan duration-sum gap). Investigated Claude Code's native `claude plugin eval` harness directly (`case.yaml`/`graders/*.md`) rather than guessing — it's real but gated to early access on this account (confirmed via `claude plugin eval init --bare`, returned "currently in early access"), so these cases run as a manual protocol for now, written to migrate cleanly once access opens rather than inventing a parallel custom runner.
- **Live-data boundary documented honestly (`agent-loops` §2c), not oversold.** Investigated `acceler-kg-sync` directly: `knowledge/files.json`/`graph.json`/`instr_candidates.json` are genuinely live (12h cron, Drive+4 Sheets→Supabase→republished into this plugin's `knowledge/` folder automatically, 1,833 files as of this check) and now documented as query-able by any reviewer needing to locate a real artifact. The separate "Delivered Curriculum Graph" is **not** yet machine-readable — it exports as `index.html` only, no JSON — so the existing "ask for objectives, never invent" behavior across this whole skill family is confirmed still correct, not a stopgap. Concrete next step named, not built here (different repo): extend `acceler-kg-sync`'s export to emit a `curriculum.json`.
- **Continuous-improvement mechanism defined** (`evals/README.md`): three feedback sources — the eval set (regression protection, grows on every real false negative/positive), per-skill Memories logs (repeated dismissals signal a rubric miscalibration to fix, not a one-off to keep dismissing), and impact-report data (PRD Phase 3, not yet flowing — the intended future input for recalibrating the Pacing/Difficulty and Engagement Ratio lenses against real outcomes instead of static rules).
- **Explicitly out of scope, not silently dropped:** the checklist's Module Upload section (Uplevel folder/access/resource-collection steps) and Before/During/After-the-Class Ops-team steps are platform/ops-tracking concerns — Control Panel/Live Tracker territory, consistent with the existing plugin/Control-Panel boundary. The checklist's Primary Research / Curriculum Design / Timeline Planning / SME Mapping section is a pre-content process-readiness gate conceptually adjacent to `discovery-fit-review` but not yet built out as its own check — flagged for a future pass, not invented now without real grounding.
- **`post-sales/agents/` (NEW)** — every hat is now a real, plugin-namespaced subagent (`acceler-post-sales:deck-reviewer`, `:code-demo-reviewer`, `:mcq-reviewer`, `:assignment-reviewer`, `:hands-on-guide-reviewer`, `:project-reviewer`, `:coherence-reviewer`), not prose telling a generic agent to "act independently." All 7 reviewer agents ship with `disallowedTools: Write, Edit(, NotebookEdit)` — they cannot edit a file even if instructed to try. Only `:content-fixer` has edit access, and it's only ever invoked with one pre-approved finding. This closes a real gap: a research subagent in this same session ignored a plain-language "don't edit files" instruction earlier during grounding research — a tool-level restriction can't be talked past the way a prompted one can. Every skill's §2/§3 and every command now name the actual agent instead of saying "independent Agent call." Caveat documented in `agent-loops/SKILL.md` §3: `content-fixer`'s edit access can't be scoped to "only this artifact" at the frontmatter level (no path-based tool restriction exists), so that specific boundary is still instruction-enforced — any fixer output touching a rubric/objectives file should be treated as an automatic escalation, not reviewed as a normal fix.

## acceler-post-sales [0.1.0] — 2026-07-28

### New plugin — split out of acceler-presales
- **`acceler-post-sales`** (NEW plugin, same repo, `post-sales/` subdirectory) — delivery/post-sales artifacts now version and install separately from the pre-sales pipeline: `session-deck` (live delivery deck), `session-recap` (post-delivery learner recap), `session-recap-report` (post-delivery stakeholder analytics).
- **Why:** `acceler-presales` is a pre-sales orchestrator by name and by the majority of its commands (discovery, similar, proposal, proposal-deck, pricing, instructors). Session deck and session recap are delivery-phase artifacts generated after the deal closes, for a different moment in the lifecycle and often a different user. Splitting them into their own plugin makes both names accurate and lets either be installed/updated independently.
- Moved from `acceler-presales` into `acceler-post-sales`: `commands/session-deck.md`, `commands/session-recap.md`, `commands/session-recap-report.md`, `skills/live-session-deck/`, `skills/session-recap/`.
- Both plugins are listed in the same `.claude-plugin/marketplace.json` (`acceler-local`), so one `/plugin marketplace add` still gets you both; install either or both with a separate `/plugin install`.
- `commands/setup.md` (in `acceler-presales`) updated: the `live-session-deck` workspace symlink now targets `acceler-post-sales`'s own plugin cache path, and the "what to run next" listing is split by plugin.

## acceler-presales [0.3.0] — 2026-07-01

### Deck commands split — pre-sales vs post-sales
- **`/acceler-presales:proposal-deck`** (NEW) — the pre-sales PITCH deck. Client-facing proposal/solution deck on the KASE engine (data-driven `SLIDE_DATA` slides, ~80 templates).
